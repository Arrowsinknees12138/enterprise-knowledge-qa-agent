# 需求与验收

员工需要查询内部制度或产品 FAQ，并能从原文核对答案。输入为问题和可选的上下文消息。系统使用带文档 ID、版本日期和片段 ID 的合成资料，提供检索与原文读取。

成功回答应有相关原文、文档 ID、版本日期和 `answered` 状态。材料冲突时应查证适用范围或优先级，缺依据时列出双方原文并请求确认。未找到资料时应写明缺口。工具故障、模型错误与步数耗尽需要各自可识别的状态。

| 场景 | 验收标准 |
| --- | --- |
| 明确答案 | 从 D03 原文回答门禁开通时长，并提供可核对的引用 |
| 文档冲突 | 读取 D01/D02，补查适用依据，列出两个期限并请求确认 |
| 资料外问题 | 明示缺口，回答字段和引用为空 |
| 同义改写 | “刷卡进楼”类问法仍能获得同一门禁制度原文 |
| 上下文追问 | 用历史确定“那要等几天”所指的主题，重新从本轮资料取证 |
| 工具失败 | 分别注入检索和读取失败，保留实际失败观察，结束为 `tool_error` 并说明缺失的证据 |
| 相似候选与多片段 | 在附件与云盘等相似资料中找到相关制度，引用支持所问字段的具体片段 |
| 可判定的适用关系 | 有明确替代声明或适用人群时，选择相应原文并引用 |
| 执行限额 | 区分决策步数和实际工具调用次数。证据充分时允许在工具预算为零的情况下结束 |

交付范围是单用户、单次 CLI 问答和可复现验证。语料固定为小型合成知识库，替换语料后可用相同 CLI 运行。
