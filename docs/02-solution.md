# 设计与取舍

## 一轮决策的执行方式

1. CLI 把问题和可选历史作为一份结构化输入。历史提供上下文线索。
2. 真实模型通过原生函数调用选择 `search_docs`、`read_doc` 或 `finish`，并给出一句可公开的依据。
3. 运行时校验参数，执行一个动作，把结果以工具消息送回模型。参数不合法时也返回错误观察，给模型纠正机会。
4. 模型依据新观察选择下一步。例如找到一个明确来源后结束，发现两个相异期限后补查，或者读取持续失败后报告工具错误。
5. 每步记录动作、参数、依据、观察和后续动作。预算内没有通过结束校验时返回 `step_limit`。

## 检索与引用

检索先做 Unicode 归一化、大小写折叠和标点过滤，再累计命中词的逆文档频率权重。每个词的权重为 1 除以包含该词的文档数。工具返回前五个候选及分数、候选总数和其中尚未读取的文档 ID。候选只含元数据，必须再用文档 ID 读取原文。用 `--data` 替换语料后，检索和引用均读取新文件。

`finish` 接收片段 ID。运行时只接受本轮实际读取过的片段，由程序从工具结果填充引用文字和版本日期。给出明确答案前要核对已发现候选。要提交冲突结果，必须引用至少两份已读文档，并在读完这些文档后成功执行一条新的检索。模型决定补查词和后续结论，运行时检查补查顺序和查询新颖性。

最终答案采用原文摘录以便逐字核对。返回 `insufficient_evidence` 时只给出缺口和可选的澄清问题，已读原文保留在 Trace 中供排查。冲突缺口使用受控文案，澄清问题由模型填写。一般的语义相关性和冲突判断依赖模型，日期仅作为元数据。

对于无对话历史、同时明确询问起算事件和工作日期限的问题，若模型提交资料不足，执行器可以核对唯一已读候选的 `deadline` 标注。核对包括适用人群、主题、办理主体和办理动作，并要求整条已读原文包含显式起算条件和工作日期限。全部匹配时，程序引用实际读到的原文并在 Trace 记录纠正。天数取自当前原文，额外的计日规则、其他人群或有多个候选的情况由原有问答流程处理。

## 技术选择

用 Python 标准库实现 CLI、JSON 和 HTTP。知识库足够小，关键词别名与少量工具便于审查。没有引入 Agent 框架。真实模式默认用 DashScope `qwen-plus` 的 Chat Completions 兼容接口，离线模式则以固定规则调用同一个执行器。[兼容接口文档](https://www.alibabacloud.com/help/en/model-studio/compatibility-of-openai-with-dashscope.md)

DeepSeek 提供方复用同一套工具 schema、HTTP 请求和观察消息。该提供方显式关闭思考模式并设定 `tool_choice=required`，使模型每轮在已注册动作中选择。DeepSeek 配置从独立密钥变量读取，默认使用官方端点和 `deepseek-flash`。[DeepSeek 工具调用文档](https://api-docs.deepseek.com/guides/tool_calls/) · [Chat Completions 参数](https://api-docs.deepseek.com/api/create-chat-completion/)

`search_docs` 和 `read_doc` 都是只读操作。默认每次请求最多 8 轮模型决策、6 次实际业务工具调用，两项预算可独立配置。一次真实执行无论成功或失败都扣工具预算，参数校验拒绝的动作只占决策步数。本轮已经成功的相同归一化查询或原文读取可以重用，Trace 标记 `cached: true`，并保留各步剩余预算。

工具预算为零时，模型仍可从已有证据选择 `finish`。需要执行新工具时返回 `tool_limit`，没有通过结束校验且模型步数耗尽时返回 `step_limit`。业务工具与模型接口分别报告各自的失败状态。
