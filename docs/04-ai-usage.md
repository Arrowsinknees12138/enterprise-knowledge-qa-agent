# AI 使用记录

候选人在对话中提供题面、确认选择第 3 题，并授权创建仓库和实施项目。

Codex 辅助范围包括方案与接口选择、合成知识库、CLI 与 Agent 实现、测试用例、文档、GitHub 操作和验证。项目运行时的 `qwen-plus` 负责选择动作，和辅助开发的 Codex 分开记录。

关键修改由 Codex 根据实际运行提出并实现。首轮模型发现两条冲突原文后跳过补查，且将缺少效力信息的文档描述为现行有效。随后增加冲突结束校验和受控缺口文本，并补上回归测试。[首轮实际输出](../examples/initial-conflict.json)

Codex 已执行单元测试、Mock CLI 和真实模型 CLI 验收，结果见[评估记录](03-evaluation.md)。候选人本人独立修改、代码审阅和复跑的记录待本人据实补充。

候选人后续要求接入 DeepSeek，并通过本机输入密钥启动官方 API 验收。Codex 实现提供方切换与测试，分析首轮缺少证据时的引用差异，并修复最终输出。[评估记录](03-evaluation.md)

候选人提出扩展测试集、验证效果并增加工具预算。Codex 扩充合成语料，实现检索排序、工具预算与会话内结果复用，运行离线和真实模型验收。[本轮验收](03-evaluation.md)

候选人确认追加冻结对照评估。Codex 拟定题目和标准答案、先提交用例再跑 DeepSeek 基线，并根据历史制度用例的引用问题修改提示词。改动前后使用相同语料和评分器复跑。候选人独立出题、标注和复跑的贡献需要据实记录。[对照评估](03-evaluation.md#冻结对照评估)

候选人随后要求新增 30 题，发现问题后直接尝试修复并推送。Codex 拟定和冻结六类场景，扩展评分器，实跑 DeepSeek，复核失败 Trace 并修正对时限、上下文指代和政策适用人群的判断规则。[30 题评估](03-evaluation.md#30-题场景评估)

候选人要求把场景测试扩展到 50 题。Codex 拟定新增 20 题和标准答案，扩展评分器以核对指定文档读取和答案数值，实跑全部题目并复核失败记录。复核发现 S45 的预期超出原文，随后修订标注并保留原评分和 Trace。[50 题评估](03-evaluation.md#50-题场景评估)
